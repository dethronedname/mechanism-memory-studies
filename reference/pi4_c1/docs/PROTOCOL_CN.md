# PI-4 C1：冻结设计后的独立数据确认

日期：2026-09-21。新协议 `PI4-C1-independent-data-confirmation-v0.1-20260921`。

## 1. 为什么运行，为什么不叫PI-5

PI-4 GPU01出现有限的机制差分和重组预测正信号，但它只来自一套生成数据、三个初始化，且原逐元素CPU回放容差失败。C1检验这些效应是否在新生成的训练／验证／测试数据上重复，不开发新模型、不调损失、不把原失败改成通过。本协议在已知旧结果后制定；它是前瞻性的独立数据确认，不冒充从未接触旧证据的预注册研究。

## 2. 原样冻结的科学内容

`pi2/`及`pi4/`共10份Python源码逐字继承原PI-4包，其中包括模型、模拟器、目标函数、验证选模、拟合和预测代码。SHA256在 `provenance/ORIGINAL_CORE_SHA256.json`。新代码仅在 `c1/`、新的执行入口和配置中。

五种方法仍是 fixed_mse / fixed_behavior / free_mse / free_behavior / ode_behavior。
候选2维固定上下文+2维动态状态，主对照4维自由状态。所有方法拥有相同校准信息及辅助标签。持久维数匹配不等于训练参数量或函数族相等。普通ODE保留为完整对照，不重新增加或更换基线。

16点历史；普通16步、重置32步训练；两套校准，每套2段48点；训练256、验证32、测试48组；学习率0.003、AdamW衰减1e-6、宽24／历史宽16；行为权重均0.25；一般batch6／配对batch4；1600次更新、每100步验证；clip_grad_norm=5。训练等待0/16、测试等待0/256。全部保持原配方。

初始化第0步也参与验证选模；只使用一般与重置两类未加权验证NMSE等权平均；两套校准视图均纳入验证。不得按测试差分、校准一致性或GPU时间改选检查点。

FP32、eager，不做编译/BF16/TF32扫描。新执行器在每个实际工作进程显式关闭TF32。继续使用服务器已有PyTorch/CUDA环境，不升级环境以争取数值通过。记录版本；框架不承诺跨版本逐位相同。

## 3. 独立层级和规模

三套新生成数据：d01=921101，d02=922101，d03=923101。初始化811、821、823在每套数据内配对重复。45次拟合=3数据×3初始化×5方法。

所有源数据随机流的偏移区间已检查不与PI-4旧CPU/GPU数据种子范围、也不在三套新数据间重叠。数据生成规律、样本数、参数区间、拓扑和激励分布不变；只换随机抽样。它们是三个独立生成数据集，不是九个独立数据集，也不是不同模拟器或真实测量数据。

执行顺序先按初始化分块，在块内用固定 schedule_seed=921901打乱模型和数据集顺序，不按胜负调整。一次启动全部计划，无开发搜索、先验筛选或中途扩展。

## 4. 数据与测试隔离

新输出目录；任何已有目录均拒绝覆盖。父执行器必须确认全部45个拟合正常退出、完成1600步、最佳权重哈希匹配，才写全局 `TEST_RELEASE_LOCK.json`。所有数据集均完成训练后，才能评估任何一套测试。

沿用模拟器生成全部标签；生成标签不等于允许训练读取测试标签。训练代码只加载 train_g2/train_g4/train_reset/val_g2/val_g4/val_reset；真实机制参数留在 scoring_only，任何学习器不读取。隔离是工作流约束，不是加密或操作系统权限隔离。

缺失、超时、BUDGET_STOP、数值失败时保持INCONCLUSIVE；不得解释成无学习收益。已经完成的训练和失败均保留。不重试，不补选种子，不解除锁继续训练。

## 5. 冻结主终点和逐数据集判定

在每套数据内部，按相同初始化比较 fixed_behavior / free_behavior。

* 主效果：reset_iso和reset_ring4的256步等待后 `difference_error`（E_delta）比值，将两场景×三初始化的6个正比值取几何平均，必须≤0.90。
* 一般质量保护：ring4、ring8、long8三个场景分别先求配对MSE比，再取三初始化中位数；各项必须≤1.05。
* 重复方向：每个初始化将两个差分场景的误差比取几何平均，至少2/3小于1。

这些是原PI-4效应门槛，在每套新数据独立应用。三个数据集都通过才标记 `REPLICATED_WITHIN_SIMULATOR`；部分通过为 `PARTIAL_REPLICATION`；一个都不通过为 `NOT_REPLICATED`。缺失必要证据或数值保真未通过则INCONCLUSIVE。状态不触发更多实验。

阈值±0.001内、或GPU保存预测与CPU回放改变通过/不通过分类，标记数值边界敏感并保持INCONCLUSIVE，不移动门槛。该0.001只处理边界不确定性，不给予候选额外性能宽限。

统计报告以三套数据为重复层级，完整保留逐数据集与逐初始化，不把轨迹、节点、预测元素或2×2格子视为独立训练证据。不用只有三个数据集的区间制造“已统计确认”结论；报告数据集范围、几何平均与一致性。相同更新数不等于严格同墙钟，无加速宣称。

## 6. 机制与边界检查不得被主平均覆盖

保留全部原9个场景记录、所有预测：同机制A/B校准差异、错机制校准交换、零差分边界、等待0/256、多部件重组、普通和长期预测。记录四个2×2组合与普通ODE，提供log误差尺度上的描述性2×2差分，不能称统计交互定理。

同机制更换校准引起的预测MSE、它占真实差分能量的比例，以及错机制交换的误差比都必须显示。不临时扫描一致性权重；本轮也不新设一个由旧分数调出来的校准一致性胜负阈值。

即使主门槛通过，若一致性仍差，只能说可保留并可用的机制信息带来有限收益，不能称机制不变量已正确识别。E_delta=1可对应零差分预测；必须显示绝对E_delta，不能只用相对坏基线的改善夸大读取能力。

正确方程的积分辨识是上一轮已经建立的信息充分性参照。本轮不反复运行该参照，不将它的旧测试分数混入新数据的排名；源码仍保留，但无自动灰箱运行或事后新对照。

## 7. 数值规则：旧判定保留，新协议预先分层

旧GPU01逐元素容差FAIL与监督器INCONCLUSIVE永久保留。C1不声称修复旧模型，不改变原 `provenance/legacy_scripts/audit.py`。

### 7.1 有限实路径预检

在d01的训练数据前2行上，对五方法×（general、reset wait0、reset wait16）共15条路径，比较CPU FP32、CUDA FP32和CPU FP64。相同初权重、真实目标、clip_grad_norm=5和一步AdamW。比较loss、原参数梯度、更新量以及两个Adam矩状态。相对门槛分别1e-3、3e-3、0.03、3e-3、0.006。任何路径失败不启动拟合。不调整门槛重试，不增加BF16／编译矩阵。

### 7.2 拟合后完整回放

所有45份最佳权重在CPU FP32上按独立编排完整前向：每模型9场景×主/替代/错配=1215个数组。独立用float64重新计分、重建数据内容哈希、复核验证最优检查点和2×2同初始化。使用相同底层模型实现，不冒充独立重写了ODE求解器。

原 rtol=atol=2e-5 的逐元素判断仍全量输出，包括超差数与最大差，不在第一处中止。

新保真门槛：每个数组的差值RMS除以相应训练标签RMS≤1e-4，最大绝对差除以训练标签RMS≤1e-3；原MSE、重复MSE、错配MSE、差分MSE经相同训练能量归一化后的改变≤1e-4；非零真差分的E_delta改变≤1e-4。零差分场景不伪造分母，直接保留未归一化误差。NaN/Inf或形状不一致失败。

所有保存指标独立重算的误差按1+|原指标|归一化须≤1e-12；验证分数重放绝对差≤1e-4。每个检查点还固定抽reset_iso等待256的前2对做CPU FP64预测探针，使用同一数组保真门槛。此有限FP64探针不替代完整FP32回放。

新规则是参考已知旧平台漂移、在看新数据前设计的任务保真准则，不是“从理论证明的通用容差”。它不仅看门槛分类，也直接约束所有预测和指标。旧逐元素FAIL可以与新保真PASS同时出现，两个标签都必须保留。

## 8. 资源和GPU边界

已有分配的单卡CUDA逻辑cuda:0，沿用A100平台可减少额外环境变化；80GB不是已测最低显存需求。保留CUDA_VISIBLE_DEVICES，不提交调度器任务，不换GPU、不多卡、不重装PyTorch/CUDA。

每次拟合900秒硬上限，其中20秒用于收尾；必须完成1600步才纳入正式判定。全流水线最多50400秒（14小时），包括数据、预检、失败、预测、CPU回放和报告；这是资源上限，不是预计耗时或必跑额度。控制器预留9000秒用于后处理，剩余不足时不启动新拟合。退出回收少量超限开销单独计费，绝不用于增加更新。

最多45次拟合的逐进程上限合计11.25小时，但不保证极端情形下整个矩阵一定在总额内完成。总额先到就停止，保留PARTIAL/INCONCLUSIVE，不追加预算。任何不完整比较不解封测试。正式确认只有一个运行目录，不通过反复新建目录隐性续跑。

## 9. 交付前与正式结果分开
