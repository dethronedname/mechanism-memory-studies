# PI-4 T1：固定完整拟合时间的质量比较

日期：2026-09-22。协议 `PI4-T1-v0.1-20260922`。这是读取B1结果后提出的新、前瞻性比较；不是从未看过任何相关数据的注册。旧B1的 `MIXED_TRADEOFF_NO_DOMINANCE`、C1的部分重复及旧逐元素失败均不改写。

## 1. 唯一主问题

给各方法同样的完整单次拟合时间上限后，固定机制记忆＋行为监督能否保留相对持续读取校准的普通模型的质量优势？本轮不研究新结构、不做微基准、不要求单步更快，也不以跑更多种子替代原本未通过的条件。

B1支持部分同更新数优势，但候选一次1600步进程中位数约431.7秒，宽GRU约85.1秒、图GRU约120.1秒。详见`provenance/B1_GPU01_REVIEW_CN.md`。这些数值仅用于说明比较缺口，不能据此猜测新预算下谁赢。

## 2. 保留原模型和训练配方

六种方法全部保留：`fixed_behavior`、`free_behavior`、`gru4_behavior`、`gru32_behavior`、`graph32_behavior`、`node32_behavior`。模型工厂、六种计算图、PI4目标函数、模拟器及旧数值函数共17份B1 Python文件逐字保留，见`provenance/B1_FROZEN_PYTHON_SHA256.json`。

候选与旧自由模型的持久状态均为每部件4个标量；小GRU为2动态＋2上下文；三种宽基线为16动态＋16上下文。参数量与B1相同（1510/1892/1198/4082/8786/3970），并非等参数消融。所有方法有相同校准、查询历史、连接图和监督，不读取隐藏机制标签，不在预测期间输入真实未来状态。

B1原开发锁原文随包保留。六种方法的学习率全部为0.003，本轮无新搜索。AdamW、权重衰减1e-6、clip=5、两个行为权重0.25、批次6/4、输入编码与验证分数定义保持不变。

保留配方意味着本轮检验的是已开发配方的成本—质量，而非每种模型在600秒下重新调优后的性能上限。不得根据此次测试分数选择新学习率、容量、早停门槛、等待时间或训练预算。

## 3. 真正改变的因素：从更新数改为时间

正式单次拟合总上限为 **600秒**。不再设1600步停止点；每种模型只要有时间，就继续按原批次序列学习。100000步仅是异常保护：触发即标记`INCONCLUSIVE`，不算完成600秒比较。CPU烟雾测试的两步上限绝不能进入GPU配置。

### 3.1 统一时钟和计费

父进程在创建新训练进程前读取`time.monotonic()`，将同一个起点传入worker；父进程deadline也是这个起点＋600秒。计入Python/torch导入、源码核验、读取和上传训练/验证数据、CUDA初始化、模型和优化器初始化、前反向、验证、所有检查点序列化和哈希、结果写入、退出。没有免费热身或免费编译。本轮FP32 eager，TF32关闭，不做BF16、compile或其他执行模式搜索。

训练步和验证结束做CUDA同步，日志中的已完成工作不依赖尚未结束的异步队列。使用官方时钟与CUDA语义的依据见`docs/SOURCES.md`。父进程有独立的退出状态；worker打印COMPLETE不能覆盖父进程TIMEOUT。

同一上限不等于所有方法实际恰好占用600.000秒。预算内固定预留30秒收尾，近截止时根据已观察到的更新/验证成本停止新更新；实际拟合时间、训练净时、验证与保存成本、剩余时间全部回传。已知成本的预估只用于保守停止，不保证不会TIMEOUT；超时仍记失败。达到既定时间停机是正常完成，不再沿用“没有训练够1600步就BUDGET_STOP”的旧判定。

### 3.2 验证选择不偏向快模型

第0步验证，此后按**完整拟合墙钟每30秒**安排一次验证，结束前至多一次最终验证；不再每100步验证。若一次操作跨过多个时间槽，只执行一次，不追补多份相同权重的验证。方法之间获得相同的预定检查频率，实际有效检查次数仍逐一公开。任何慢验证、保存和落盘都计入该模型预算。

每次验证保存单独检查点及四个时间戳：验证开始、验证完成、检查点落盘、检查点哈希完成。只有验证分数和对应权重均已在截止前完成，才有资格参与该时刻的最优验证选择。开始得早但保存超时的点不能回填。按最小验证分数选择；完全平分时选更早完成的检查点。最后的`best.pt`复制和进程退出也必须在600秒内。

主测试只评估600秒合格检查点。150/300秒记录只用于**同一训练轨迹的验证曲线**，不解封额外测试、不事后选最有利预算，也不冒充两个独立冷启动实验。短预算无合格检查点时写`NOT_AVAILABLE_WITHIN_BUDGET`，不从未来借权重。

### 3.3 成本边界

公共模拟数据准备、有限预检、测试和完整CPU回放不算某个方法单次拟合，但全额计入运行器研究账。公共生成资料对全部方法相同；单次数据读取和设备上传仍按模型计费。历史B1学习率搜索是已发生的开发成本，随锁保留，不能把“本轮没有搜索”解释为方法此前不需要搜索。全研究投入与单次拟合上限不混为一谈。

## 4. 三套新数据与固定规模

同一模拟器和分布，数据基点t01=2422101、t02=2522101、t03=2622101；初始化971/977/983。与B1/C1随机范围不重叠，不续训旧权重。

3套数据×3初始化×6模型＝**54次拟合**。没有DEV分支。每个dataset/seed块包含全部六个方法，按固定旋转顺序串行执行，平衡早晚位置；块顺序提前随机化，不并发争抢同一GPU，也不根据结果改顺序。

256/32/48组训练/验证/测试；校准每套2段48点；查询历史16点。一般训练16步、重置32步；训练等待0/16，测试等待0/256；一般ring4/ring8/long8与reset_iso/reset_ring4/reset_null均保留。

所有54次拟合完整成功、主检查点预算与哈希检查通过后才统一释放测试集。缺失、异常保护、TIMEOUT、非有限值不得丢弃后报告幸存者。已有测试锁不删除、不覆盖；本协议一旦进入测试阶段，不再允许训练。

## 5. 判定标准不随时间结果更改

使用B1既定指标和比较函数，逐数据集、逐对照报告，不在测试中选择唯一赢家。

候选相对某对照：两个等待后机制差分场景的配对误差比几何平均≤0.90；ring4/ring8/long8各自配对中位比≤1.05；至少2/3初始化的机制综合方向有利。反向5%匹配规则也完全保留；这只是工程门槛，不是统计等效性检验。

* `LIMITED_TIME_BUDGET_SIGNAL`：候选对全部对照、三套数据全部通过原门槛。
* `BASELINE_MATCHES_AT_EQUAL_TIME`：至少一个持续校准新增对照在全部三套数据满足5%匹配标准。
* `MIXED_TIME_BUDGET_TRADEOFF`：其余完整有效情形。明确取舍，不自动延长。
* `INCONCLUSIVE`：执行、完整性或数值证据不足；不是架构没有收益。数值临界或回放改变分类仍保持这一状态。

报告必须包括绝对E_delta、一般误差、同机制换校准、错机制校准、步数、各阶段成本、参数量、持久状态、峰值allocator显存。不能用坏基线上的比例改进替代准确机制辨识。三套同模拟器数据不是三个真实应用；没有Transformer/Mamba或官方公开基线完整复现，也不能声称通用主流领先。

## 6. 数值与证据

18组有限FP32预检：六模型×一般/重置0/重置16三路径，使用同配方、裁剪后AdamW和CPU64参照。沿用B1阈值。

正式主权重全部CPU32回放；每份权重固定reset_iso等待256的前2对做CPU64探针。保留旧逐元素标签和既定任务保真阈值，不因微小超差停止其余权重审计，也不放宽旧标准。回放独立组织前向与指标但共用模型源码，不冒充独立模型实现。

所有中间检查点、训练JSONL、验证曲线、时钟、超时和失败都回传。只排除可再生的数据NPZ并提供内容哈希。早期检查点不用于正式测试。

## 7. 资源、启动和结束

使用已有单卡CUDA分配，逻辑`cuda:0`，保留CUDA_VISIBLE_DEVICES。无GPU则54项NOT_RUN、退出码2；不安装/更换PyTorch CUDA、不自行申请服务器或多卡。

拟合上限54×600秒＝9小时。运行器总上限16小时，包括公共数据、预检、失败、测试和CPU回放；留4小时后处理，并检查15分钟归档余量。这是资源上限，不是预计耗时。启动前文件核验与单元测试、此前实施工作单列，不冒充计入每次600秒。归档即使发现超预算仍保存证据，并在旁附校验文件标明资源超限。

一旦完整比较结束即收束：普通模型匹配时降低特殊结构不可替代主张；候选保留优势时只支持此任务、此预算与锁定配方；继续取舍时保留取舍。不自动延长、续训、增加损失、修改模型或启动kernel优化。

**准备阶段只完成CPU工程验证；正式GPU结果必须等实机执行后才能填写。**
